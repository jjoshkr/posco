# 릴레이 패널 보드 — 구조와 Linux 에서의 단계별 동작 확인

대상: Raspberry Pi 5 + Relay_module_v1 HAT(릴레이 제어보드) + Relay_40pin_32CH(32CH 릴레이 보드), 점검 프로그램 `hardware/relay_panel/relay_panel.py` (설명서 `relay_panel_manual.pdf`).

## 0. 전체 구조 — 한 줄로

```
Pi 5 ──I2C-1(GPIO2 SDA, GPIO3 SCL)──▶ MCP23017 ×2 (U1 0x20, U2 0x21) ──▶ ULN2803A ×4 (싱크 드라이버) ──40핀 리본──▶ 릴레이 32개 (코일 5 V) ──▶ 단자 J1~J32 (L–N–FG)
      └ GPIO27 = RST (두 칩 리셋, HAT 에 10 kΩ 풀업)                    코일 전원: HAT J3 의 5 V → 리본 5,10,…,40번 핀
```

- **명령 경로**: Pi 가 I2C 로 MCP23017 의 출력 래치(OLAT)에 비트를 쓰면 → 그 핀이 High → ULN2803A 가 해당 출력을 GND 로 끌어내림 → 5 V 가 걸린 릴레이 코일에 전류 → 접점이 붙음.
- **번호 규칙**: 릴레이 n = 릴레이 보드 Un = 단자 Jn. 칩 하나가 16개. **포트 B 가 앞 8개, 포트 A 가 뒤 8개** (S1~8 = U1 GPB0~7, S9~16 = U1 GPA0~7, S17~24 = U2 GPB0~7, S25~32 = U2 GPA0~7).
- **전원 두 계통**: 3.3 V(Pi 헤더 1·17번)는 MCP23017 로직용, 5 V(HAT **J3 단자**)는 릴레이 코일용. J3 에 5 V 가 없으면 통신은 되는데 릴레이는 안 붙음. 코일 1개 24 mA, 32개 0.77 A.
- **극성·초기 상태**: MCP 출력 1 = ON. 전원을 켠 직후 MCP 핀은 입력이라 전부 OFF. 프로그램이 끝날 때 전부 OFF. 단 `kill -9`·재부팅처럼 정리 없이 끝나면 마지막 상태가 남는다 → 부하를 달면 비상정지(5 V 또는 24 V 차단)가 따로 필요.
- **이 프로젝트에서의 역할**: 릴레이 1~4 = 솔레노이드 XV-101~104 (밸브 보드 거쳐 24 V), 나머지는 예비. 펄스(펌프 접점)는 릴레이가 아니라 MCC 152 채널보드의 PC817 이 맡는다 ([BOARDS.md](BOARDS.md)).

## 1. 꽂기 전에 (전원 OFF)

| 확인 | 기준 |
|---|---|
| 주소 점퍼 | 모듈 1(U1) JP1~3 전부 뺌 = 0x20, 모듈 2(U2) **JP6 만 꽂음** = 0x21. 둘이 같으면 릴레이 1 을 켤 때 17 도 켜짐 |
| 리본 케이블 | HAT J2 ↔ 릴레이 보드 J33, 1번 핀(빨간 줄) 방향 같게. 180° 돌아가면 +5 V 와 신호가 바뀌어 여러 릴레이가 한꺼번에 동작 |
| J3 5 V | 5 V 2 A 이상 어댑터. 릴레이 4개만 쓰면 Pi 의 5 V 핀(27 W 전원)에서 끌어와도 되지만, 32개면 별도 전원 |
| 220 V | **연결하지 않음**. 릴레이 보드 J34(L/N/FG) 비운 채 5 V 만으로 아래를 끝낸다 |
| MCC 스택 | 첫 시험은 **Pi + 릴레이 HAT 만**. MCC 보드는 통과한 뒤에 올린다 (3절) |
| 납땜 눈검사 | MCP23017 9번(VDD 3.3 V)·10번(VSS)·12번(SCL)·13번(SDA)·18번(RESET), ULN2803A 9번(GND)·10번(COM = +5 V) 브리지 여부 |

## 2. Pi 에서 단계별 (SSH 또는 모니터)

### 2-1. I2C 켜고 버스 확인

```bash
sudo raspi-config nonint do_i2c 0
ls /dev/i2c-1
sudo apt install -y i2c-tools
i2cdetect -y 1
```

기대: 표에 `20` 과 `21` 두 칸만 채워짐. 하나만 보이면 점퍼가 같거나 한 칩이 죽은 것. 아무것도 없으면 SDA/SCL 납땜·HAT 방향·3.3 V.

### 2-2. 점검 프로그램으로 자가진단

```bash
cd ~/dye_color_matching/hardware/relay_panel
python3 relay_panel.py --cli --installed 1,9,17,25
```

`--installed` 는 지금 릴레이를 납땜한 채널(설명서 기준 1, 9, 17, 25). 32개 다 달았으면 `--installed all`.
시작하면 자동으로 스캔과 자가진단이 돈다. 기대하는 기록 네 줄은 모듈 1·2 의 RST 확인, 통신·레지스터 정상, 두 모듈 "연결됨". 자가진단이 하는 일은 설명서 5장에 있다: 주소 응답 → 레지스터 모양으로 칩 종류 확인 → GPIO27 리셋 펄스가 먹는지 → 쓰기/읽기 무늬 비교 → 래치 0 으로 둔 뒤 출력 전환.

### 2-3. 릴레이 하나씩

```
relay> on 1        # 릴레이 1 ON  → 딸깍
relay> info 1      # 신호 경로: U1 GPB0 → U3 O1 → 헤더 1번 → U1 → J1
relay> off 1
relay> on 9        # U4 확인
relay> on 17       # U2 칩 + U5 확인
relay> on 25       # U6 확인
relay> off
```

각 단계에서 멀티미터 도통 모드로 **J34 의 L(1번) ↔ Jn 의 L(1번)**: ON 이면 도통, OFF 면 개방. 소리는 나는데 도통이 없으면 접점 쪽 납땜.

### 2-4. 순차·동시·장시간

```
relay> walk 1.5        # 납땜한 채널을 1.5 초씩 차례로
relay> on inst         # 납땜한 채널 전부 ON → J3 전압 측정(4.75 V 이상 유지), 수 분
relay> walk 0.5 all    # 32채널 전부 (릴레이 없는 채널도 MCP 핀까지는 검사됨)
relay> q
```

"칩이 리셋되었습니다" 가 켜는 순간 나오면 5 V·GND 배선(전압 강하)을 의심. 릴레이 없는 채널의 ULN2803A 출력까지 보려면 헤더 +5 V 핀과 그 채널 핀 사이에 LED + 1 kΩ 을 임시로.

### 2-5. 프로그램 없이 레지스터로 직접 (원리 확인용, 선택)

```bash
i2cset -y 1 0x20 0x14 0x00 0x00 i   # OLATA, OLATB = 0 (전부 OFF)
i2cset -y 1 0x20 0x00 0x00 0x00 i   # IODIRA, IODIRB = 0 (출력)
i2cset -y 1 0x20 0x15 0x01          # OLATB bit0 = 1 → 릴레이 1 ON
i2cget -y 1 0x20 0x13               # GPIOB 되읽기: 0x01 이면 핀도 High
i2cset -y 1 0x20 0x15 0x00          # OFF
```

순서가 중요하다. 래치를 0 으로 쓴 **뒤에** 방향을 출력으로 바꿔야 전환 순간에 릴레이가 튀지 않는다.

## 3. MCC 스택과 같이 쓸 때

1. **주소 충돌 확인**: MCC 152 의 DIO 도 같은 버스의 MCP23017 이고 주소가 0x20 + 보드 주소다. `hardware/io_node_rev_b.json` 대로 MCC 152 를 주소 2·3 에 두면 0x22·0x23 이라 릴레이 HAT(0x20·0x21)과 겹치지 않는다. 스택을 올린 뒤 `i2cdetect -y 1` 에 20, 21, 22, 23 이 모두 보여야 한다.
2. relay_panel 의 버스 스캔은 응답이 정확히 둘일 때만 자동 설정하므로, 스택이 있으면 `--addr 0x20 0x21` 로 명시한다. **0x22·0x23 을 고르면 MCC 152 DIO 에 써 버린다.**
3. 스택 순서: 아래부터 MCC 118(0) → MCC 152 a(2) → MCC 152 b(3) → MCC 134(4) → 맨 위 릴레이 HAT. 릴레이 HAT 는 SPI·GPIO12/13/26/21 을 쓰지 않아 MCC 와 핀이 겹치지 않는다. 높이가 안 맞으면 40핀 리본으로 옆에 둔다.
4. cmysim 으로 넘어가기:

```bash
cp hardware/io_node_rev_b.json io_node.json
pip install smbus2
python -m cmysim.io_node_main run --pump-mode pulse -v
```

cmysim 은 시작할 때 쓰는 릴레이 핀만 출력으로 바꾸고(래치 0 먼저), GPIO27 을 출력 High 로 잡고, 종료·SAFE 때 전부 OFF 한다. 밸브 명령 `valve XV-101 open` 이 릴레이 1 을 켠다. relay_panel 과 cmysim 을 **동시에** 띄우지 말 것(둘 다 같은 칩에 쓴다).

## 4. 자주 나오는 증상 (설명서 7장 요약)

| 증상 | 원인 |
|---|---|
| 20, 21 안 보임 | HAT 방향, 3.3 V, SDA/SCL 납땜 |
| 주소 하나만 | 점퍼 같음 |
| 1 을 켜면 17 도 | 점퍼 같음 (두 칩 모두 0x20) |
| 1 을 켜면 17 이 | 모듈 주소를 서로 바꿔 입력 |
| 기록 정상인데 소리 없음 | J3 5 V 없음, 리본, ULN2803A |
| "명령 ON 인데 핀 Low" | 그 MCP 핀 납땜 브리지 |
| 켜는 순간 "칩 리셋" | 5 V 전압 강하 → GND 배선 굵게, 전원 가까이 |
| 어느 버튼을 눌러도 여럿 동작 | 리본 180° |
